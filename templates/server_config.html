OpenSSH (Linux / macOS / WSL / Windows 10+)

Trust signed host keys (no more "authenticity ... can't be established"): 

echo '@cert-authority *.{{ server_url.split('//')[1].split(':')[0] }} {{ ca_pubkey or "<CA pubkey>" }}' >> ~/.ssh/known_hosts

Trust signed user certs (so an sshd you administer accepts certificate-authenticated logins): 

# /etc/ssh/sshd_config (or a drop-in under sshd_config.d/)
TrustedUserCAKeys /etc/ssh/sshadmin_ca.pub
# then on the host:
sudo curl -fsSL "{{ server_url }}{{ url_for('api_ca_pubkey') }}" -o /etc/ssh/sshadmin_ca.pub
sudo systemctl reload ssh
PuTTY (Windows)

PuTTY 0.78+ supports SSH host certificates. To pin the CA so any host carrying a sshadmin-signed cert is auto-accepted:

  1. Open PuTTY Configuration → Connection → SSH → Host keys.
  2. Under Manually configure host keys for this connection, click Add and paste the CA public key (the entire line shown above starting with {{ ca_key_type or 'ecdsa-sha2-...' }}).
  3. Tick the Treat as a certification authority box.
  4. Save the session so it persists.

Older PuTTY (< 0.78) does not support host CAs; in that case you'll have to accept the host key manually on first connect.

TeraTerm (Windows)

TeraTerm pins host keys per host the first time you connect (TOFU). It does not natively support a CA-trust list. Workarounds:

  1. Connect once, accept the host key, and TeraTerm will remember it in %APPDATA%\teraterm5\ssh_known_hosts (or similar).
  2. Or distribute that ssh_known_hosts file with the host fingerprints already in place, generated by: 
    ssh-keyscan -H your-host >> ssh_known_hosts
Verifying a signed host cert from any client
ssh-keygen -L -f /etc/ssh/ssh_host_ecdsa_key-cert.pub
