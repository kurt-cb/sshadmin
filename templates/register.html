Step 1 — Generate an SSH Key Pair
{# ── Linux / macOS ─────────────────────────────────────────────── #}

Requires ssh-keygen (part of OpenSSH, installed by default on Linux and macOS).

Option A — sshadmin dedicated key (recommended)

ssh-keygen -t ecdsa -b 521 -f ~/.ssh/id_sshadmin -C "$(whoami)@$(hostname -s)"

Creates ~/.ssh/id_sshadmin (private) and ~/.ssh/id_sshadmin.pub (public). Paste the contents of the .pub file into Step 2 below: cat ~/.ssh/id_sshadmin.pub

Option B — Ed25519 (also recommended)

ssh-keygen -t ed25519 -f ~/.ssh/id_sshadmin -C "$(whoami)@$(hostname -s)"

Option C — Zero-touch via sshadmin (does everything automatically)

If you already have SSH access to this machine from another enrolled machine, download the helper script and run it — no manual key pasting needed: 

curl -fsSL "{{ url_for('download_sshadmin_add', _external=True) }}" -o sshadmin && chmod +x sshadmin
./sshadmin $USER@$(hostname -s)

This generates keys, registers them with sshadmin, installs certificates, and configures sshd — all in one step. The registration flow below is still needed for your first account if you don't yet have sshadmin.

{# ── Windows PowerShell ────────────────────────────────────────── #}

Requires Windows 10 version 1809+ or Windows Server 2019+ with the OpenSSH Client optional feature installed. Run in a regular (non-admin) PowerShell session.

Generate ECDSA P-521 key

ssh-keygen -t ecdsa -b 521 -f "$env:USERPROFILE\.ssh\id_sshadmin" -C "$env:USERNAME@$env:COMPUTERNAME"

Display the public key to paste into Step 2

Get-Content "$env:USERPROFILE\.ssh\id_sshadmin.pub"

Generate Ed25519 key (alternative)

ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\id_sshadmin" -C "$env:USERNAME@$env:COMPUTERNAME"

If ssh-keygen is not found, install the optional feature:
Add-WindowsCapability -Online -Name OpenSSH.Client~~~~0.0.1.0

{# ── PuTTY ─────────────────────────────────────────────────────── #}

Use PuTTYgen (included with PuTTY) to generate a key. PuTTY 0.78+ supports ECDSA and Ed25519.

  1. Open PuTTYgen (search the Start menu).
  2. Under Type of key to generate, select ECDSA and set the curve to nistp521 — or select EdDSA for Ed25519.
  3. Click Generate and move your mouse over the blank area to generate entropy.
  4. Set a Key comment (e.g. yourname@yourpc-sshadmin) and optionally a passphrase.
  5. Click Save private key — keep this file safe.
  6. The text box at the top shows the OpenSSH public key (starting with ecdsa-sha2-nistp521 or ssh-ed25519). Copy the entire line and paste it into Step 2 below.
PuTTY uses its own .ppk private key format. To complete the registration challenge (Step 3), use the SSH option on the next page — connect to sshadmin's SSH server with PuTTY and submit the token interactively.
{# ── TeraTerm ──────────────────────────────────────────────────── #}

TeraTerm 4.x+ includes a built-in SSH key generator.

  1. Open TeraTerm. Go to Setup → SSH Key Generation…
  2. Select ECDSA and bits 521 (or ED25519).
  3. Click Generate. Move the mouse over the blank progress bar to generate entropy.
  4. Optionally add a passphrase.
  5. Click Save public key — save as id_sshadmin.pub.
  6. Click Save private key — save as id_sshadmin (or id_sshadmin.ppk).
  7. Open the saved .pub file in a text editor. Copy the line that starts with ecdsa-sha2-nistp521 or ssh-ed25519 and paste it into Step 2 below.
To complete the challenge (Step 3), use the SSH option on the next page to connect to the sshadmin SSH server with TeraTerm and submit the token interactively.
{# ── Dropbear ──────────────────────────────────────────────────── #}

Dropbear uses its own key format, but you can generate an OpenSSH-compatible public key to paste here.

Generate a key with dropbearkey

dropbearkey -t ecdsa -s 521 -f ~/.ssh/id_sshadmin_dropbear

Extract the OpenSSH-format public key (paste this into Step 2) 

dropbearkey -y -f ~/.ssh/id_sshadmin_dropbear | grep "^ecdsa"

To complete the challenge using dbclient (Step 3) 

dbclient -p {{ ssh_port or '2222' }} -i ~/.ssh/id_sshadmin_dropbear {{ sshadmin_host or 'sshadmin-host' }}

Then paste the token shown on the next page when sshadmin prompts Token:.

Dropbear's dbclient does not support ssh-keygen -Y sign (the SSHSIG format used by the one-liner script). Use the SSH interactive option on the next page instead.

{# PuTTY ──────────────────────────────────────────────────────────────── #}

Trust host certificates — PuTTY does not support OpenSSH-format CA host verification directly. For full certificate support, use the Windows PowerShell tab with OpenSSH for Windows, or configure PuTTY to use an OpenSSH-compatible CA via Connection > SSH > Host keys.

OS / Unix Username — your Windows account name (shown in Settings > Accounts) or the unix username on the remote machine.

Already have an account? Log in

What Happens After Registration?
  1. Your account is created and your public key is registered.
  2. A user certificate (-cert.pub) is issued alongside your key.
  3. In PuTTY, load your private key (.ppk) in Connection > SSH > Auth. PuTTY will automatically present the matching certificate if it is in the same directory.
  4. Connect to the enrolled machine — authentication proceeds via certificate.
PuTTY 0.78+ supports SSH certificates. Ensure your PuTTY version is up to date. The -cert.pub file must be placed alongside the .ppk file.
{# TeraTerm ───────────────────────────────────────────────────────────── #}

Trust host certificates — TeraTerm uses its own KNOWNHOSTS file and does not support OpenSSH CA-based host verification. Host certificate checking will not apply; TeraTerm will prompt on first connection as usual.

OS / Unix Username — your Windows account name or the remote unix username.

Already have an account? Log in

What Happens After Registration?
  1. Your account is created and your public key is registered.
  2. A user certificate (-cert.pub) is issued. Download it from the Certificates page.
  3. In TeraTerm: Setup > SSH Authentication — set your private key file. Place the -cert.pub file in the same directory.
  4. Connect to the enrolled machine — TeraTerm will use the certificate for authentication.
TeraTerm SSH certificate support varies by version. TeraTerm 5.x with the TTSSH module supports OpenSSH certificates. Check your version before proceeding.
