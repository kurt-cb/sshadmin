Key Concepts

What is an SSH Certificate?

An SSH certificate is a signed public key. Unlike the traditional authorized_keys approach — where every server must store a copy of every user's public key — certificates work differently:

  • A Certificate Authority (CA) signs a user's public key, producing a certificate.
  • Each server is configured to trust the CA (one line in sshd_config).
  • When the user connects, the server verifies the certificate against the CA — no per-user configuration needed.

This means adding or revoking a user's access doesn't require touching every server; you control it centrally through certificate issuance and expiry.

Host Certificates vs. User Certificates
Host Certificates

Prove that a server is who it claims to be. Replaces the "do you want to trust this unknown host key?" prompt clients see on first connection. Once the CA is in the client's known_hosts, any CA-signed host is trusted automatically — no per-host fingerprint to manage.

Signed by the site-wide Host CA (same CA for all hosts).

User Certificates

Prove that a user is allowed to log in. The certificate lists the unix account names the user may access (principals). The server checks that the cert is CA-signed and that the requested login name is in the principals list.

Signed by a User CA — in multi-group mode, each group has its own User CA key.

Certificate Principals

Principals are the unix usernames a user certificate authorises. For example, a cert with principals alice,deploy lets the holder log in as alice or deploy on any machine that trusts the signing CA.

Important: A cert with principal root would grant root access to every machine that trusts that CA. sshadmin does not allow root as a principal for this reason. Root access must use traditional per-machine SSH keys.
Certificate Validity and Expiry

Every certificate has a validity window. When it expires, the holder can no longer log in — without any action required on the servers. This is the primary revocation mechanism:

  • Long-lived certs (default: 365 days) — convenient for persistent access.
  • Short-lived certs (1 hour or less) — ideal for temporary or on-demand access. Authorization is checked at issuance time; a revoked user simply cannot get a new cert.

The sshadmin update and sshadmin updatehost commands automate renewal before a cert expires.

The sshadmin CLI Tool

The sshadmin shell script (downloadable from the Hosts page) automates the full enrollment flow from an already-enrolled machine:

CommandWhat it does
sshadmin user@hostEnroll a new host: generate keys, register, install certs, configure sshd
sshadmin update user@hostRenew the user cert if expiring within 30 days
sshadmin updatehost user@hostRenew the host cert (requires sudo on remote)
sshadmin alias user@hostRegister current IP/name as a host alias, re-issue cert
sshadmin update_cert user@hostRe-issue host cert with all stored aliases
